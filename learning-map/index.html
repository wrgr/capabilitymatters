About this resource · How to use it · Learning engineering connections

What is this resource?

A searchable map of learning guides organized by practical questions about systems, AI, evidence, design and making.

How should I use it?

  1. Choose a question or follow one stop in the suggested route; you do not need to complete every resource.
  2. Use search, Learning question and Resource type to narrow the guides, then open one and try its activity.

How does this connect to LENS and learning engineering?

The map helps connect a capability question to an activity and a proposed test. Compare what a resource lets you observe with what evidence would be needed for learning, transfer or impact; navigation progress alone is not evidence of capability.

Start with a question. Explore one experience. Explain what you noticed, then choose a next step.

You can use any resource independently. These routes are suggestions; you do not need to finish everything.

Four moves to carry with you

  1. Orient — Why this? What will I learn?
  2. Explore — Try one task with a prediction.
  3. Digest — Explain a result and another possible cause.
  4. Connect — Name a new setting and a next test.

If you feel lost, pause here.

Too much information?

Choose one guide and one task. Write a prediction before opening the project. You can leave the other material for later.

Unsure what it means?

Write “I observed…” and “I think this happened because…” separately. Then ask what else could explain the result.

Unsure where to go next?

Return to the process if the problem is unclear. Compare another example if the explanation is unclear. Plan a test if the evidence is unclear.

A few terms that help you navigate
Capability
The capacity of a person, team, or human-system arrangement to accomplish valued work under stated conditions, with usable opportunities to act. Capability depends on the coupling of learner performance with system performance; human flourishing supplies its purpose. Read the working definition in Capability Matters.
Learning engineering
A systematic, iterative approach to designing learning experiences and using evidence to improve them.
Transfer
Using what was learned in a different task or setting.
Prototype
A small implementation or proposed design used to examine an assumption.
Instrumentation
Deciding what to observe or record so a result can inform a decision.
Falsifying evidence
A result that gives you a reason to reject or revise an assumption.
