# Capability Matters site feedback responses

This record addresses the October 19 feedback and the earlier pasted feedback against the current site. Changes are prepared in the website PR; creating this record does not publish them. Older About and Welcome references are interpreted through their current aliases rather than reinstating a second orientation page.

## October 19 feedback

### Motivation page status

The page is the site’s introductory argument, not an unlabeled empty placeholder. It now explains that the site evolves and that individual working drafts and unvalidated demonstrations are labeled at the resource. The page should orient visitors before they choose a case, lab or prototype; it does not claim that every linked resource is complete or validated.

### Cold black background

Replaced the homepage’s dark navy presentation with a warm cream background, dark text and deep green links. The navigation, lab card, definition section and footer use the same warm palette. The existing content and responsive layout are retained. This supersedes the older request to turn purple text white on the former dark presentation: dark readable text on a light background meets the intent without retaining the cold background.

### Goal of the page

An opening paragraph now states the goal: explain why capability belongs in system design. It defines learning engineering in plain language and links Start Here for choosing a resource. Start Here is the practical welcome and orientation page.

## Accessibility

Semantic headings, main/navigation landmarks and labeled controls remain in use. New explanations use native details/summary elements, which work by keyboard and do not require hover. Active navigation is also underlined, and outcome labels use words rather than color alone. Visible text contrast was checked on the six revised routes; a low-contrast Andon count badge was corrected. Focused keyboard and responsive checks accompany the build and pipeline tests. These checks are not a claim of complete WCAG conformance across every embedded application and every possible state; existing accessibility audits remain relevant.

## About and Start Here

### Use About as Welcome

Already addressed in the current structure: Start Here provides background, pathways and direction. The old About route renders the same content. There is no need to maintain two competing welcome pages.

### Make Case Studies and Experiments links prominent

The pathway destination labels are bold and underlined. Each explains what visitors can do there.

### Show Your Work as a top tab

Added Show Your Work to the shared desktop and mobile primary navigation and to the standalone Approach host. The working-paper page has its own active-navigation state.

### Seven domains wording

Changed “Seven recur” to “Seven domains recur” in Where it applies. Here domains means professional settings such as healthcare or aviation.

### Definitions for the five competencies

Each named competency on Start Here now has a keyboard-operable expandable explanation. The measurement competency is named Data, Measurement and Evaluation, and the fifth is Navigating Sociotechnical Constraints, matching the curriculum framing.

### Domain versus competency

The LENS framework section now calls the five practices competencies. Professional settings remain domains. The Case Studies explanation distinguishes setting domains from competency tags.

### James Diamond affiliation

Added School of Education immediately after James Diamond’s name in People and programs.

### Learning Engineering Commons link

The first Scope and caveats item now links Learning Engineering Commons directly.

### IEEE ICICLE link

The second Scope and caveats item links IEEE ICICLE directly.

### Where to report broken links

The broken-link item links the repository’s new-issue page and asks for the page address and the link attempted. A contact email remains available as an alternative.

### Repository link for contributing

The Contributing section now links the source repository itself as well as issues and contact email.

## Former Welcome feedback

### Contrast and text color

The homepage now uses a warm light palette and high-contrast dark text. Start Here already uses the light shared site shell. The request for white text belonged to the former dark presentation and is superseded by this change.

### This site features

The opening explanation begins “This site features” and describes the whole site rather than narrowing it to three fictional projects. Current lab copy does not freeze the project count at three.

### Background on learning engineering

The opening paragraph describes applying learning sciences, human-centered design and evidence to improve what people can do. Start Here connects that definition to concrete exploration paths.

### Purpose of fictional projects

The Agentic AI Lab card explains that fictional problems make decisions, disagreements and revisions available for practice without presenting them as deployments with real learners. It retains the distinction between real agent execution and fictional problem settings.

### Explain the Agentic lab button

The link is labeled Explore the Agentic AI Lab and sits below a description of candidate products and decision replays. It does not imply enrollment or a validated training intervention.

## Case Studies

### Uppercase What

The heading is now “Case Studies: What happened, and what can we learn?”

### Explain how to read the page

Added a reader guide explaining What failed/What worked, comparisons, topic domains, competency tags and evidence limits. The pasted “This needs explanation” had no identifiable highlighted element; the new guide addresses the page’s main interpretive elements rather than claiming to have identified an absent annotation.

## Experiments and Andon

### Explain the three experiment categories

Existing descriptions remain under each category. An expandable key before the category links explains learning labs, research and practice projects, and creative demonstrations together, and states that these labels do not establish effectiveness.

### Explain the full shift controls

The Andon host includes a keyboard-accessible control guide for Start shift/Next decision, Run/Pause, Plus one minute, Slow/Normal/Fast and Pause at decisions. It distinguishes playback speed from simulated task duration and distinguishes the full-shift controls from guided practice and the scripted demo.

### Explain workstations

The same guide defines Receiving, Pick and Label, and Dispatch as the fictional work sequence. It explicitly distinguishes workstations from capability-pipeline stages.

## Prototypes

### Explain the pipeline steps

The sidebar now presents seven numbered steps with an expandable definition for each. Refine is unnumbered and continuous; Evaluate returns to Understand. Per-card refinement is also unnumbered. Legacy simulation data retain their original refinement phase, which is identified separately rather than silently renumbering the engine.

### Explain collection abbreviations

Added an expandable collection key for AILE, LXD, LENS and LENS Canonical. It expands each name and explains that Canonical identifies recurring system-problem briefs in this collection, not an approval or effectiveness rating.
