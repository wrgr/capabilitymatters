Inside the workforce candidate

Readiness beyond course completion helps a new team lead rehearse a fictional feedback decision, consider another explanation, revise an approach and recover from an interruption. Its reflection is descriptive; it does not assess employees.

The handoff contains executable HTML, requirements, versioned artifacts, the project journal and a source-linked manifest. It is a candidate product requiring affected-person review and field validation.

Reusable roles and proficiency targets

Roles inherit a common contribution contract, then specialize by discipline and relevant domain. They reference the five LENS competency domains. Requested proficiency describes the contribution expected in a simulation; demonstrated proficiency requires separately reviewed task evidence.

The existing exemplar used earlier fixed prompts. Its history is preserved without retrospectively assigning these new targets. Future runs pin the resolved role profiles and their versions in the journal.

From candidate to operational product

Understand → Map → Design → Build → Instrument → Deploy → Evaluate → Refine is a revisitable cycle. Build produces the executable candidate; refinement can return to any invalidated requirement. The learning engineer integrates the work and keeps human and system requirements visible.

Real use needs accountable ownership, affected-person review, appropriate data handling, accessible operation, a meaningful comparison and stopping rules. Learning, workplace transfer and flourishing remain claims to investigate. Inadequate conditions can justify changing the product, changing the work system, or stopping.

The hosted site serves saved products and replay. New model runs use the local runner in this repository; hosted model access and a shared job queue remain future work.
